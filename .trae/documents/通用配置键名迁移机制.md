# 快捷按钮配置：通用键名迁移 + 默认值补全机制

## Context（背景）

此前把配置键 `文件暂存路径` 改名为 `临时文件路径`，并要求"缺失走默认值"。但：

1. **加载/导入老配置时没有任何迁移**：老按钮里仍是旧键 `文件暂存路径`，新键缺失。
2. 资源监控等运行时代码用**裸索引** `config['临时文件路径']`（非 `.get`），老配置一加载就抛 `KeyError`——已实测：资源监控「下载数据」报"没有临时路径"，启动监控（L649）、清除数据（L1160）同样会崩。
3. 用户要求做**通用机制**而非只修这一个键：以后任何键改名，都应自动迁移、缺失补默认、只保留识别到的键。

目标：建立一份"每种指令类型规范键 + 默认值 + 旧键映射"的单一真相源，在配置进入内存的唯一收口点统一规范化；并对少数关键裸索引加 `.get` 兜底。

## 现状关键事实（已核对）

- 配置进入内存的唯一底层通道是 [add_button](file:///d:/github/OneClick/MainWindowLogic.py#L895)；启动加载 `load_sc_config`(L3395) 与导入 `import_config_dialog`(L3220) 最终都调它，且传入的 config 均为各自的 `.copy()`，**就地规范化安全**。
- `add_button` 把 `config_data` **原样引用**存入 `sc_buttons[id]['config']`(L978)；第 933 行 `config_data['指令类型']` 是裸索引。
- 9 类按钮及规范键已由调研完整梳理（见下）；已有 `_normalize_command`(L3489) 仅处理"指令"字段格式，可复用但不覆盖按钮级迁移。

## 实施方案

### 1. 新建 `utils/config_schema.py`（纯数据 + 纯函数，单一真相源）

- **`TYPE_SCHEMAS`：每种指令类型的「规范键 → 默认值」**（键集合即"允许保留的键"）：
  - `发送命令` / `发送命令并接收回显`：IP、用户名、密码、端口('')、指令('')、指令名称、临时文件路径('')
  - `发送文件`：IP、用户名、密码、端口、指令名称、临时文件路径、源路径列表([])、服务器路径('')
  - `获取文件`：同上，将 服务器路径 换为 目的路径
  - `复制本地文件`：指令名称、源路径列表([])、目的路径('')
  - `资源监控`：SSH 五键 + 指令名称 + 临时文件路径 + 进程('')、采样频率('')、监控时长('')、监控时长单位('天')、嵌入式(False)
  - `弱网`：SSH 五键 + 指令名称 + 临时文件路径 + 规则列表([])、循环次数('0')、网卡('')（规则项内的 带宽单位 属于列表子项，不在顶层裁剪）
  - `服务器检查`：指令名称、服务器检查配置({})
  - `记事本`：指令名称、内容('')
  - 每类都含 `指令类型`、`指令名称`。
- **`RENAMES`：旧键 → 新键映射**，分全局与按类型：
  - 全局：`文件暂存路径 → 临时文件路径`
  - 发送文件：`目的路径 → 服务器路径`；获取文件：`本地路径 → 目的路径`；复制本地文件：`复制到 → 目的路径`
  - （源列表**嵌套项**的旧结构 `文件名包含/本地路径/...` 不在本次重命名范围，沿用现有运行时兼容逻辑。）
- **`FRAMEWORK_KEYS = {'分组', '位置'}`**：框架注入键，规范化时原样保留、不裁剪、不补默认。
- **`normalize_button_config(config) -> dict`**：
  1. 读 `指令类型`；若类型不在 `TYPE_SCHEMAS`（无法识别/损坏）→ 记日志并**原样返回**，保证不崩、不丢数据。
  2. 先应用全局、再应用类型专用 RENAMES：旧键存在且新键缺失时搬值，随后删旧键。
  3. 以该类型 schema 为准重建结果：schema 中的键——有现值用现值、缺失补默认值（= 只保留识别到的键，未知键丢弃）。
  4. 合并保留 `FRAMEWORK_KEYS` 中实际存在的键。

### 2. 在收口点接入（[MainWindowLogic.py](file:///d:/github/OneClick/MainWindowLogic.py)）

- `add_button` 开头：`config_data = normalize_button_config(config_data)`，使 L933 裸索引、以及 load/import 两条上游链路一并收口；规范化后 `指令类型` 必有值（未知类型为 ''，由现有 `click_map.get(...) → None → 报错返回` 优雅处理）。
- `edit_button` 的 `.update()` 之后对该 config 再调一次规范化（编辑保存后旧键即被清除、新键补齐）。

### 3. 关键裸索引 `.get` 兜底（有限范围，防手动粘贴/手改 json 的毒数据）

- 资源监控三处 `['临时文件路径']` 改 `.get('临时文件路径', '')`：[L649](file:///d:/github/OneClick/dialogs/resource_monitor_dialog.py#L649)、[L1160](file:///d:/github/OneClick/dialogs/resource_monitor_dialog.py#L1160)、[L1401](file:///d:/github/OneClick/dialogs/resource_monitor_dialog.py#L1401)（缺失时空串，由后续 `resolve_work_dir` 回退家目录）。
- 不做全项目几十个裸索引的机械替换：迁移层已保证内存中配置始终规范；其余为编辑回显路径，风险低，避免无谓改动。

## 影响与边界

- 老配置首次启动即被规范化，下一次自动保存（`_save_config_auto`）落盘后，文件中键名全部更新，无需逐个编辑。
- 未知类型的损坏配置不裁剪、原样保留，仅记日志，避免误删。
- `分组/位置` 等框架键不受影响，布局不乱。

## 验证

1. `python -m py_compile` 编译新增/修改文件。
2. 构造含旧键 `文件暂存路径`（及各类旧路径键）、缺失多个新键的 config.json：启动后断言 ① 旧键消失、新键继承原值；② 缺失键补默认；③ `分组/位置` 保留；④ 未知类型配置原样保留。
3. offscreen 冒烟实测老"资源监控"按钮：启动监控、下载数据、清除数据三条链路不再 KeyError；下载在缺路径时回退家目录。
4. 导入配置（追加/覆盖）同样验证迁移生效。
